What is DSA, really?
Before we dive into any code.
Data Structures are ways to organize and store data so a computer can work with it efficiently. Same data, completely different experience depending on how you organize it — like the difference between a messy pile of papers and a well-labeled folder system.
And what are algorithms?
An Algorithm is a step-by-step set of instructions to solve a problem. Like a recipe. The data structure is your kitchen — the algorithm is what you do in it.
Why does this matter?
🎮
Every app, game, and website you've ever used runs on data structures under the hood. When GTA V loads a city, it uses spatial data structures. When you press Ctrl+Z to undo, that's a Stack. When matchmaking puts you in a game queue, that's literally a Queue.
📱
Your phone contacts? That's a Dictionary. Your Spotify playlist on repeat? Circular Linked List. Browser history with back/forward buttons? Doubly Linked List. You already live in a world of data structures — now you get to understand them.
The big picture
Problem → Choose the right Data Structure → Apply an Algorithm → Solution Example: "Find a student's marks" → Dictionary → key lookup → marks in O(1) time
You've already been doing data structures — we're just putting names on them now. 🌸

List
An ordered, changeable collection of items.
A List stores multiple items in a single variable, in a fixed order. Items can repeat, you can add/remove/change them any time. It's the most flexible and beginner-friendly structure in Python — and probably the first one you ever used.
What it looks like
numbers = [10, 20, 30, 40] ↑ ↑ ↑ ↑ index: 0 1 2 3 numbers[0] → 10 numbers[2] → 30
Core operations
numbers = [10, 20, 30] numbers.append(40) # add 40 to end → [10,20,30,40] numbers.remove(20) # remove value 20 → [10,30,40] numbers.sort() # sort smallest → biggest numbers[0] # access by index → 10 len(numbers) # count of items → 3 max(numbers) # largest item set(numbers) # removes duplicate values
Advantages vs disadvantages
Advantages
Easy to use. Direct index access. Built into Python. Dynamic size. Loads of built-in methods.
Disadvantage
Inserting or deleting from the middle shifts everything else — slower for large lists.
Real-world uses
Student marksShopping cartGame inventoryTo-do listLeaderboards
🛒
Think of it like: A shopping list. Everything's in order, you can add items, cross things off, or rearrange the whole thing.
"Lists are the 'I'll do everything myself' data structure."

Stack
Last In, First Out — LIFO.
A Stack works like a pile of plates — you can only ever add or remove from the top. Whatever you added last is the first to come out. That rule is called LIFO.
Visual structure
← TOP (last added, first to leave) ┌─────────┐ │ 30 │ ← Push 30 last ├─────────┤ │ 20 │ ├─────────┤ │ 10 │ ← Pushed first └─────────┘ ← BOTTOM
Core operations
stack = [] stack.append(10) # Push → add to top stack.append(20) # Push stack.append(30) # Push stack.pop() # Pop → removes 30 (last added) stack[-1] # Peek → see top element (20) without removing len(stack) == 0 # Check if empty
Advantages vs disadvantages
Advantages
Push and pop are instant. Simple to build. Perfect for tracking states and history.
Disadvantage
You can only directly access the top element. No random access by index.
Real-world uses
Ctrl+Z undoBrowser back buttonFunction call stackExpression parsing
🍽️
Think of it like: A pile of plates. You always place a new plate on top, and always take from the top. Nobody digs from the bottom.
"The last one to arrive gets VIP exit privileges."

Queue
First In, First Out — FIFO.
A Queue is fair by design — whoever arrives first, leaves first. You add to the back (enqueue) and remove from the front (dequeue). That rule is called FIFO.
Visual structure
FRONT BACK ↓ (exits here) (enters here) ↓ [ 10 ] → [ 20 ] → [ 30 ] → [ 40 ] dequeue removes 10 next enqueue adds to the right end
Core operations
queue = [] queue.append(10) # Enqueue → add to back queue.append(20) queue.append(30) queue.pop(0) # Dequeue → removes 10 (first added) queue[0] # Front → see first element without removing len(queue) == 0 # Check if empty
Stack vs Queue — the key difference
Stack (LIFO): add → [10, 20, 30] → remove from RIGHT (30 leaves first) Queue (FIFO): add → [10, 20, 30] → remove from LEFT (10 leaves first)
Advantages
Fair ordering. Easy to implement. Great for task scheduling and anything that needs to be processed in order.
Disadvantage
pop(0) is slow for very large queues — it shifts every element. Use collections.deque for speed.
🧍🧍🧍
Think of it like: A queue at a counter. You join at the back, you're served from the front. Cutting in line is not allowed (and also illegal in this data structure).
"The only data structure that actually respects the queue."

Dictionary
Key-value pairs for fast, meaningful lookups.
A Dictionary stores data as key : value pairs. Instead of searching by position (like a list does), you search by a meaningful name — the key. Think of it as labeling everything so you never have to count to find it.
Structure
students = { "Parvathy" : 95, ← key : value "Arjun" : 88, "Meera" : 92 } students["Parvathy"] → 95 (instant lookup!)
Core operations
students["new_name"] = 90 # Add a new entry students["Parvathy"] = 97 # Update existing value del students["Arjun"] # Delete entry "Meera" in students # Check if key exists → True/False students.items() # Get all key-value pairs # Loop through all students for name, marks in students.items(): print(name, ":", marks)
Advantages
Extremely fast lookups. Intuitive key-based access. Perfect for organizing structured data.
Disadvantage
Keys must be unique — duplicate keys overwrite each other. Uses more memory than a plain list.
Real-world uses
Phone contactsLogin systemsStudent recordsConfig settingsWord counters
📱
Think of it like: Your phone contacts. You search by name, not "contact number 47." The name is the key, the phone number is the value.
"Instead of remembering where something is, dictionaries remember what it's called."

Singly Linked List
Nodes connected in one direction.
A Singly Linked List is a chain of nodes. Each node stores a value and a pointer to the next node. Unlike a list, there's no index — you always start from the head and walk forward.
What a node looks like
class Node: def __init__(self, value): self.value = value # stores the actual data self.next = None # points to the next node (None = last node)
How the list looks
head ↓ [10 | next] → [20 | next] → [30 | None] ↑ last node (next = None, the chain ends here)
Traversal — walking through
current = head # start at first node while current is not None: print(current.value) # print current value current = current.next # move to next node # Output: 10 → 20 → 30 → None
Deletion — skipping a node
Before: [10] → [20] → [30] → None Delete 20: current.next = current.next.next After: [10] → [30] → None (20 is disconnected — nothing points to it anymore)
Advantages
Dynamic size. Easy insertion/deletion at ends. No wasted memory — grows only as needed.
Disadvantage
Can only move forward. No random access — must walk from the start to find anything.
🚂
Think of it like: Train compartments. Each compartment only knows the one ahead of it. To reach compartment 5, you have to walk through 1, 2, 3, 4.
"Every node knows exactly one friend."

Doubly Linked List
Nodes connected in both directions.
A Doubly Linked List is exactly like a singly linked list — except each node also remembers its previous neighbor. You can now travel both forward and backward through the list.
Node structure — the extra pointer
class Node: def __init__(self, value): self.value = value # stores the data self.next = None # points to next node → self.prev = None # points to previous node ← (NEW!)
How the list looks
None ← [prev | 10 | next] ⇄ [prev | 20 | next] ⇄ [prev | 30 | next] → None head last node
Traversal — both ways
# Forward (left to right) current = first while current is not None: print(current.value, end=" ⇄ ") current = current.next # Backward (right to left) current = third while current is not None: print(current.value, end=" ⇄ ") current = current.prev
Singly vs Doubly — key difference
Singly: [10] → [20] → [30] → None (one-way only) Doubly: [10] ⇄ [20] ⇄ [30] (both ways)
Advantages
Move forward and backward. Easier deletion — no need to manually track the previous node.
Disadvantage
Uses more memory — each node stores an extra pointer (prev). More connections to manage.
🌐
Think of it like: Your browser history. The Back button follows prev, the Forward button follows next. Both directions are remembered.
"Nodes finally decided communication should go both ways."

Circular Linked List
The last node loops back to the first.
A Circular Linked List is almost identical to a singly linked list — but with one twist. The last node doesn't point to None. It points back to the first node, making a loop that never ends.
How it looks
┌───────────────────────────┐ ↓ │ [10] → [20] → [30] → [40] ───┘ ↑ head (after 40 comes 10 again — it never reaches None)
Key setup — creating the circle
first = Node(10) second = Node(20) third = Node(30) first.next = second second.next = third third.next = first # ← THIS is what makes it circular!
Traversal — stop when you loop back
current = first while True: # can't use "while not None" — it'll loop forever! print(current.value) current = current.next if current == first: # we've completed one full loop break
Singly vs Circular — the one difference
Singly: [10] → [20] → [30] → None (ends) Circular: [10] → [20] → [30] → [10] (loops forever)
Advantages
Can traverse continuously. No need to restart from head. Perfect for cyclic repeating processes.
Disadvantage
Forget to check for the start? Infinite loop. Needs extra care during traversal.
Real-world uses
Music on repeatMultiplayer turnsRound-robin schedulingCPU process cycling
🎵
Think of it like: Songs on repeat. After the last song ends, it wraps straight back to the first one. The playlist never truly "ends."
"This linked list looked at endings and said 'nah.'"
